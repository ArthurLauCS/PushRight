# 功能入口与界面记录

对齐 Fork 的每项功能做完后在这里记一节：入口在哪、有哪些控件、状态存在哪、涉及哪些文件、和 Fork 有什么差别。写的是实际做成的样子。

「完整面板」指扩展里「打开提交图」的界面，它和桌面版共用 `src/`；「扩展原生」指源代码管理面板、侧栏紧凑提交图、状态栏和 VS Code 自带的 diff 编辑器。

## 主题微调

- **浅色主题**：底色、面板、浮起三层和边框整体压暗一档，正文从 `#141413` 调到 `#1f1e1c`。正文、次要文字、强调色、状态色和十个作者色在三层底色上的对比度都不低于 4.5:1。
- **深色主题的分支标签**：提交图里本地分支标签的底色从强调色 16% 提到 30%，边框带上强调色。新增令牌 `--ref-bg`，浅色主题下仍等于 `--accent-soft`。
- 扩展侧栏紧凑图同步：`--ref-bg` 映射到 `--vscode-textLink-foreground` 的 28%。
- 涉及文件：`src/app.css`、`src/lib/Graph.svelte`、`extension/webview/GraphView.svelte`。
- 侧栏选中行和顶部当前分支胶囊仍用 `--accent-soft`，没有改。

## Diff 工具栏

对应 Fork 文本 diff 右上角的七个按钮。

**入口**

- 桌面与完整面板：所有显示 diff 的地方上方都有同一条工具栏，靠右排列。包括本地更改页、全部提交页的提交详情、贮藏详情、仓库工具里的版本比较。
- 扩展原生：不加按钮，用 VS Code 自带的设置，对应关系见 `extension/README.zh-CN.md` 的「Diff 工具与文件树」。

**控件**（从左到右，图标按钮，悬停显示中文名）

| 控件 | 行为 | 启用态 / 禁用条件 |
| - | - | - |
| 忽略空白差异 | 引擎加 `-w` 重新取 diff | 开启时高亮 |
| 显示隐藏字符 | 空格显示为点，制表符显示为箭头；只改显示，复制出来仍是真实字符 | 开启时高亮 |
| 自动换行 | 长行在视图内折返，行号列不变，一条源码行仍是一行 | 开启时高亮 |
| 减少上下文行 | 档位 0、1、3、6、12、25、50，默认 3；提示里带当前行数 | 到 0 或「整个文件」开启时禁用 |
| 增加上下文行 | 同上 | 到 50 或「整个文件」开启时禁用 |
| 显示整个文件 | 展开全部未修改行，修改高亮保留 | 开启时高亮 |
| 并排对比 | 左旧右新，删除与紧跟的新增逐行对齐；与单栏互相切换 | 开启时高亮 |

三组之间有分隔线：空白与换行、上下文、布局。

**与按行 / 按区块暂存的关系**

- 上下文为 1 行以上（含整个文件）、并排、换行、隐藏字符下，按行和按区块的暂存、取消暂存、丢弃都照常可用。界面把当前上下文行数一起传给引擎，引擎按同样的行数重新取补丁核对区块标题。
- 忽略空白开启、或上下文为 0 行时，这些按钮隐藏，diff 顶部出现一行说明。引擎对 0 行上下文的请求也会拒绝（`PR_DIFF_FILTERED`）。
- 大文件保护不变：超过 4 MiB 或 5000 行仍走截断提示和只读分页，「整个文件」不绕过它。

**状态**

- localStorage 的 `diffPrefs`：`ignoreWs`、`hidden`、`wrap`、`sideBySide`、`context`、`tree`。全局生效，所有仓库和页签共用；完整面板里由扩展主机代存。
- 「显示整个文件」只在本次运行内有效，重启后复位。

**涉及文件**

- 引擎：`crates/engine/src/diff.rs`（`Options`、各 `*_with` 函数）、`crates/engine/src/rpc.rs`。
- 界面：`src/lib/DiffView.svelte`、`src/lib/diff-prefs.svelte.ts`、`src/lib/diff-rows.ts`、`src/lib/api.ts`、`src/lib/Icon.svelte`。
- 调用方：`WorkingCopy.svelte`、`RepoView.svelte`、`Tools.svelte`、`Detail.svelte`。

**与 Fork 的差别**

- 上下文档位、忽略空白的匹配规则（这里是 `git diff -w`，忽略所有空白变化）、隐藏字符的覆盖范围是按 Git 语义定的，Fork 的具体取值没有逐项核对过。
- 隐藏字符不标行尾符；含表情等非等宽字符的行，其后的标记可能有轻微偏移。
- 并排模式不换行时两栏共用一条横向滚动条，Fork 是两栏同步滚动。

**实测**

- 2000 行的 diff：打开约 0.4 秒；隐藏字符开关各约 0.5 秒；换行、并排开关各约 0.25 秒。
- 隐藏字符最初按空白段逐个包元素，2000 行时界面会卡住四十秒以上，已改为每行一个属性加伪元素，开关时不增删节点。

## 变更文件树

对应 Fork 文件列表的 Tree 视图和 Filter。

**入口**

- 桌面与完整面板：本地更改页左侧（未暂存、已暂存两组共用顶部一条工具条）；提交详情、贮藏详情、版本比较的「改动文件」列表（标题下方一条工具条）。
- 扩展侧栏紧凑图：展开提交后的文件按文件夹缩进显示，文件夹行不可折叠。
- 扩展原生的源代码管理面板：用 VS Code 自带的「以树查看」。

**控件**

| 控件 | 行为 |
| - | - |
| 筛选文件输入框 | 按路径包含关系过滤，不区分大小写；本地更改页过滤时分组计数显示为「显示数 / 总数」 |
| 全部展开、全部折叠 | 平铺显示时禁用 |
| 按文件夹显示 | 开关，开启时高亮；关闭即回到原来的平铺列表 |
| 文件夹行 | 点击折叠 / 展开，名字后面是其下文件数；只有一个子目录的目录链合并成一行，如 `src/lib/locales` |
| 文件夹行的暂存 / 取消暂存 / 丢弃 | 仅本地更改页，悬停出现，作用于其下所有文件；文件夹里没有可丢弃的文件时丢弃按钮禁用 |

- 文件夹排在文件前面，按名字排序；同一目录下的文件保持 Git 给出的顺序。
- 树里文件只显示文件名，悬停提示是完整路径（重命名带旧路径）；平铺时和以前一样显示文件名加目录。
- 已有的行内操作不变：状态字母、暂存、丢弃、双击切换暂存、提交详情里的「已查看」复选框（仍按路径保存）。
- 「全部暂存」「全部取消」「全部丢弃」作用于整组，不受筛选影响。

**状态**：是否按文件夹显示存在 `diffPrefs.tree`，默认开启。折叠状态和筛选词只在当前视图内有效。

**涉及文件**：`src/lib/file-tree.ts`、`src/lib/FileTree.svelte`、`src/lib/FileListBar.svelte`、`WorkingCopy.svelte`、`Detail.svelte`、`Graph.svelte`（紧凑图）。

**与 Fork 的差别**：Fork 的视图模式是 Tree / List / Combined List 三选一，这里是树和平铺两种；Combined List 的组合规则还没核对，排在阶段 6。

## 多分支筛选提交图

对应 Fork 分支行的「Show branch commits only」，这里可以同时选多个。

**入口**

- 桌面与完整面板：侧栏分支 / 远程分支 / 标签行右侧的漏斗图标（悬停出现，已选中的常亮），点一下加入或移出筛选；右键菜单有「只看这个分支的提交」「加入 / 移出提交图筛选」。
- 筛选生效时提交图上方出现一条：每个引用一个可点掉的标签，外加「清除筛选」。
- 扩展侧栏紧凑图：范围下拉最后一项「选择多个分支…」，进入多选列表，预勾当前范围。

**行为**

- 提交取所选引用的并集；共同祖先正常显示。筛选只换遍历起点，不切换检出的分支。
- 正在看的提交留着，只重新找它在第几行；它不在筛选范围内时不高亮任何行。
- 被删除的引用自动从筛选里拿掉；一个都不剩时回到全部（扩展回到 Auto）。

**状态**：桌面端存 localStorage 的 `graphScopes`，按仓库路径记引用全名列表；扩展沿用原来按仓库保存的范围值，多选时是换行分隔的引用名。

**涉及文件**：`crates/engine/src/refs.rs`（`graph_tips`）、`RepoView.svelte`、`Sidebar.svelte`、`extension/src/graph-view.ts`、`extension/src/sync.ts`、`extension/webview/GraphView.svelte`。

**与 Fork 的差别**：Fork 另有「Hide branch in commit list」（从图里隐藏某个分支），这里没有做。

## 冲突信息与提交信息

对应 Fork 冲突时的操作横幅和自动填入的提交信息。

**入口**

- 顶部黄色横幅（任何页面都在）：操作名之后多一行「正在处理 `提交号`「说明」· 第 n / m 步 · 冲突文件已解决 x / y」。步数只在变基时有。
- 本地更改页左栏最上方的「本次冲突的文件」清单：列出这次操作冲突过的全部文件，`!` 待解决、`✓` 已解决；点待解决的进入逐处解决视图，点已解决的看它暂存后的改动。
- 提交框：合并、摘取、撤销进行中时，自动填入 Git 准备好的提交信息原文，和 Fork 一样带着 `# Conflicts:` 清单（如 `Merge branch 'feature'` 加下面几行 `#` 开头的冲突文件）。
- 扩展原生界面：
  - 源代码管理面板的提交输入框同样预填；「冲突」分组的标题后面带「冲突文件已解决 x / y」。
  - 状态栏的「合并进行中」悬停提示、点开后的继续 / 中止对话框里，显示正在处理的提交、变基步数、进度，以及逐个文件的 `✓` / `!` 清单。

**行为**

- 信息直接读 Git 目录里的 `MERGE_MSG`、`MERGE_HEAD` / `REBASE_HEAD` / `CHERRY_PICK_HEAD` / `REVERT_HEAD` 和 `rebase-merge/msgnum`、`end`，不另造文案，也不启动 git 进程。
- 冲突清单取自 `MERGE_MSG` 里 Git 写的 `# Conflicts:`，所以解决之后文件仍在清单里，进度才算得出来；含中文或空格的路径会还原成原样。
- 自动填入只在提交框为空、或里面还是上一次自动填的内容时发生；用户写过的不覆盖。操作结束（提交、继续、中止）后，没改过的自动内容会清掉。
- 提交框里是什么，提交出去就是什么：提交走 `git commit -F -`，Git 不会像在编辑器里那样剥掉 `#` 开头的行，所以不删掉的话 `# Conflicts:` 清单会留在最终的提交信息里。点横幅上的「继续」则由 Git 自己用 `MERGE_MSG` 提交，注释行会被剥掉。
- 清单里含中文等非 ASCII 字符的路径，在提交框里是 Git 写下的转义形式（如 `"\346\226\207.txt"`）；界面上的冲突清单显示的是还原后的文件名。
- 变基时不预填：变基的提交由「继续」完成，不走提交框。

**涉及文件**：`crates/engine/src/conflict.rs`（`operation`）、`rpc.rs`、`RepoView.svelte`、`WorkingCopy.svelte`；扩展的 `extension/src/core.ts`、`sync.ts`、`scm.ts`。

**与 Fork 的差别**：提交框的预填内容与 Fork 一致；Fork 最终提交时是否保留 `#` 行没有核对过。Fork 的内置三栏合并编辑器、上一个 / 下一个冲突跳转没有做。

## Fast-Forward 与获取后自动快进

**入口**

- 有上游的本地分支右键 →「快进到 origin/分支」。首次会弹说明和前后示意图。
- 同一菜单的「获取后自动快进这个分支」/「取消获取后自动快进」（仅桌面版，扩展没有自动获取）。选中的分支在侧栏名字后面带一个向下箭头。

**行为**

- 当前分支执行 `git merge --ff-only 上游`，工作区文件跟着更新；其他分支执行 `git fetch . 上游:分支`，只挪引用。
- 只允许快进：本地和上游分叉时两条命令都拒绝，不会回退成合并或变基。分支被别的工作树检出、未提交的改动和新提交改到同一个文件时同样拒绝，结果写进命令日志。
- 当前分支的快进可以用「撤销」退回；其他分支的旧位置在 Reflog 恢复里。
- 自动快进接在每次**自动**获取成功之后（打开仓库时和之后每 10 分钟），手动点「获取」不触发。只处理「上游有新提交、本地没有自己的新提交」的分支；以下情况跳过并在顶部列出原因：上游不存在或已删除、已分叉、已在另一个工作树中打开、是当前分支且有未提交的改动、执行失败。已删除的分支自动从名单里拿掉。

**状态**：localStorage 的 `autoFastForward`，按仓库路径记本地分支的引用全名。

**涉及文件**：`crates/engine/src/ops.rs`（`Op::FastForward`）、`RepoView.svelte`、`Sidebar.svelte`、`explain.ts`。

**与 Fork 的差别**：Fork 的分支右键有快进，没有找到「选分支自动快进」的设置，后者是这里自己的设计。

## 交互式变基补强

入口不变：仓库工具 → 交互式变基。

**新增控件**

| 控件 | 行为 |
| - | - |
| 步骤里的提交号和说明 | 现在是按钮，点击在该步骤下方展开这个提交的改动文件和 diff（diff 工具栏、文件树都可用），再点一次收起 |
| 步骤末尾的分支标签 | 指向这个提交的其他本地分支 |
| 「同时挪动指向这些提交的其他本地分支」 | 只在有上述分支时出现，默认不勾；勾选后这些分支跟到对应的新提交上 |
| 计划摘要 | 基点 → HEAD 一行后面：执行后保留几个提交、并入前一个几个、丢弃几个；确认框里再显示一次 |
| 完成提示 | 成功后显示备份分支名；遇到冲突仍跳到本地更改页，由横幅接手 |

**行为**

- 依赖分支由引擎在执行时重新计算，不采用界面传回的列表。当前分支、被别的工作树检出的分支和 `pushright-backup/` 备份分支不算在内。
- 分支落在对应步骤之后；该步骤后面紧跟 squash / fixup 时，落在合并完成之后。被丢弃的提交上的分支落到它前一个保留下来的提交上。
- 这些分支的旧位置逐行写进命令日志（`refs/heads/x was <提交号>`）。旧提交本身仍被备份分支保留。
- 原有的校验不变：HEAD 未变化、工作区干净、提交集合完整、不含合并提交，禁用 autosquash 和 autostash。

**涉及文件**：`crates/engine/src/rebase.rs`、`rpc.rs`、`Tools.svelte`、`RepoView.svelte`、`api.ts`。

**与 Fork 的差别**：Fork 的备份分支是可选项，这里总是创建；Fork 的逐提交预览在右侧固定面板，这里在步骤下方就地展开。

## 文件类型图标与文件夹图标

- **哪里有**：本地更改页的两组文件、冲突清单、提交详情 / 贮藏详情 / 版本比较 / 变基预览的改动文件、扩展侧栏紧凑图里展开的文件。文件夹行在折叠箭头后面带一个文件夹图标。
- **怎么分**：形状表示大类（代码、文档、花括号的数据文件、设置、表格、图片、音视频、压缩包 / 二进制、字体、终端脚本、锁文件、Git 文件、Roblox 场景文件），颜色区分具体语言或格式。Luau 是蓝色代码括号，Markdown 是文档形状，两者不再相同。认不出的扩展名用灰色的空白文件。
- **扩展原生的源代码管理面板**用的是 VS Code 当前的文件图标主题，不归这里管。
- 涉及文件：`src/lib/file-icons.ts`（扩展名表）、`FileIcon.svelte`、`FileTree.svelte`、`WorkingCopy.svelte`、`Detail.svelte`、`Graph.svelte`。新增类型在 `file-icons.ts` 的表里加一行。

## Diff 语法高亮

- 所有显示 diff 的地方按文件扩展名自动高亮，配色取 VS Code 默认的深色 / 浅色主题。支持 highlight.js 常用语言集，另加 Luau、Svelte / Vue（按 HTML）、TOML（按 INI）。认不出的类型按纯文本显示。
- 区块的旧侧和新侧各自作为一段完整代码高亮，跨行的字符串和注释在区块内能认出来；从区块上方开始的多行注释看不到，着色会不准。
- 任一行超过 2000 个字符的区块不高亮（压缩过的代码）。超过 5000 行的部分本来就不显示。
- 隐藏字符、换行、并排、按行暂存都不受影响；复制出来的仍是原文。
- 涉及文件：`src/lib/highlight.ts`、`DiffView.svelte`、`src/app.css`（`--syn-*` 颜色和 `.hljs-*` 规则）。新增依赖 `highlight.js`（BSD-3-Clause，已记入第三方声明）。
- 与 Fork 的差别：Fork 设置里有「Disable syntax highlighting」开关，这里没有做开关。

## Diff 并排布局与上一处 / 下一处改动

- **并排**：两栏按比例占满视窗，不再随内容变宽，所以窗口变窄或有长行时右栏不会被推出可视范围。长行在各自的栏里裁掉，由 diff 底部一条共用的横向滚动条左右移动（Shift + 滚轮也可以），两栏一起动，行号列不动。
- **分隔条**：两栏中间可以拖动，范围 20%–80%，双击恢复对半。比例存 `diffPrefs.splitRatio`，所有仓库共用。
- **上一处 / 下一处改动**：工具栏最左边两个箭头，一段连续的增删行算一处。
- 涉及文件：`DiffView.svelte`、`diff-prefs.svelte.ts`。

## 与某个分支相比

对应「我这个分支相对 develop / main 改了什么」。

**入口**

- 侧栏分支 / 远程分支 / 标签右键：直接列出「与 develop / dev / main / master 相比」（仓库里存在哪个列哪个，本地分支优先，其次 origin 上的）和「与当前分支相比」，外加「与其他分支相比…」从全部分支里选。
- 提交图已经只看一个分支时，筛选条上有「与其他分支相比…」。
- 扩展侧栏紧凑图：范围下拉里的「与某个分支相比…」，先选要看的分支，再选基准。

**行为**

- 提交图只剩这个分支上有、基准上没有的提交（同 `git log 基准..分支`）。筛选条显示「分支 ×」「相比 基准 ×」；点掉基准回到只看这个分支。基准已经包含全部提交时显示「没有 基准 上没有的提交」。
- 筛选条上的「查看文件改动」跳到仓库工具的版本比较：起点是基准、终点是分支，自动勾选「从共同祖先开始比较」并直接出结果，看到的就是这个分支自己的全部改动。
- 版本比较多了「交换起点和终点」按钮。

**状态**：基准和筛选存在一起（`graphScopes` 里以 `^` 开头的一项；扩展是范围值里以 `^` 开头的一行）。基准分支被删除后自动退回普通筛选。

**涉及文件**：`crates/engine/src/refs.rs`（`graph_tips` 返回要隐藏的起点）、`graph.rs`、`RepoView.svelte`、`Tools.svelte`、`extension/src/sync.ts`、`graph-view.ts`、`extension/webview/GraphView.svelte`。

## 搜索提交与文件历史（桌面）

- 全部提交页顶部一条搜索栏：按提交说明、作者、文件路径、增删过的文字、提交号搜索，回车开始，每页 200 条，可加载更多。点结果跳到提交图里的那个提交；它不在当前筛选范围内时先清掉筛选。
- 文件右键「文件历史」用同一个结果列表显示这个文件的历史（跟随重命名）。
- 引擎命令是扩展原来就有的 `search` 和 `file_history`，这次只加了桌面界面。涉及文件：`CommitSearch.svelte`、`RepoView.svelte`。

## 文件右键菜单、推拉选项等小项

| 项 | 入口 | 行为 |
| - | - | - |
| 文件右键菜单 | 本地更改页的文件、提交详情 / 贮藏详情的文件 | 打开文件（系统默认程序）、在资源管理器中显示、复制相对路径、复制完整路径、复制为补丁、文件历史 |
| 只贮藏这个文件 | 未暂存文件右键 | `git stash push -- 文件`；未跟踪的文件会带上 `--include-untracked` |
| 忽略 | 未跟踪文件右键 | 仅本机忽略（`.git/info/exclude`）或加入 `.gitignore` |
| 复制名称 | 分支 / 远程分支 / 标签右键 | 复制短名 |
| 拉取时自动贮藏 | 拉取对话框第二个勾选框，默认不勾 | `git pull --autostash`：先收起未提交的改动，拉完放回 |
| 推送所有标签 | 推送对话框的勾选框，默认不勾 | `git push --tags` |
| 扩展：快进分支 | 命令面板「PushRight: 把分支快进到上游」、源代码管理面板标题栏的「…」菜单 | 列出落后于上游且没有分叉的本地分支，选一个快进 |
| 扩展：拉取时自动贮藏 | 拉取选择框的第二项 | 同桌面 |

涉及文件：`crates/engine/src/ops.rs`、`local_files.rs`（`reveal`、`patch`）、`rpc.rs`、`RepoView.svelte`、`WorkingCopy.svelte`、`Detail.svelte`、`extension/src/sync.ts`、`extension/package.json`。
